═══════════════════════════════════════════════
  SKETCHWARE PRO — PROJECT STORAGE STRUCTURE
═══════════════════════════════════════════════
Every project is stored at: .sketchware/data/{sc_id}/
  • project     — app name, package, version
  • file        — list of activities (JSON array)
  • view        — view layouts for each activity (@section text format, AES encrypted)
  • logic       — block-based logic events (JSON array)
  • library     — Firebase, AdMob, library config
  • files/java/ — Java source files
  • files/resource/ — Android resources (layouts, values, drawables)

  ═══ CRITICAL SK.txt VIEW FILE FORMAT ═══
  The view file uses a SECTION-BASED TEXT format (not JSON array!).
  Each screen has TWO sections:
    @main.xml        ← main views
    @main.xml_fab    ← FAB (required even if not used!)
  Each line in a section is one ViewBean JSON object.

  SK.txt TYPE CONSTANTS:
    0=LinearLayout  3=Button  4=TextView  5=EditText
    6=ImageView  9=ListView  12=ScrollView  13=Switch  16=FAB
  ⚠ type=2 = HorizontalScrollView (NOT TextView!) Use type=4.

  ROOT BEAN RULES (parent='root'):
    preIndex=-1, preParent="", preParentType=-1
  OTHER BEANS: preId=id, preIndex=index, preParent=parent, preParentType=parentType

  WIDTH/HEIGHT: -1=match_parent -2=wrap_content N=dp
  GRAVITY: 0=none 17=center 16=center_h 5=center_v 48=top
  COLORS (ARGB signed int): -1=white -16777216=black -13730510=#3F51B5

  HORIZONTAL LL with weight: child must have width=0, weight=1
  ALWAYS call describe_layout_live before editing any screen.

════════════════════════════════════════
  CATEGORY 8: ERROR LOGS
════════════════════════════════════════

TOOLS: get_compile_logs | get_recent_logs | analyze_code
       review_source_code | validate_rtl_layout

PIPELINE — FIX COMPILE ERROR:
  1. get_compile_logs(sc_id) ............... read FULL output
  2. Identify FIRST error: filename:line:col: error: message
  3. read_file_range(path, line-5, line+5) . see code context
  4. Diagnose root cause:
     cannot find symbol   → missing import or wrong name
     incompatible types   → type mismatch or missing cast
     already defined      → duplicate variable/method
     unreachable statement→ code after return/throw
     NullPointerException → null layout ID or uninitialized ref
  5. patch_file(path, error_context, fix) .. fix ROOT CAUSE only
  6. build_project(sc_id) .................. VERIFY
  7. Repeat from step 1 for NEXT error if still failing
  NEVER: fix 2 errors simultaneously

PIPELINE — FIX RUNTIME CRASH:
  1. get_recent_logs(sc_id, 'AndroidRuntime')
  2. Find FIRST app stack frame (your package name)
  3. read_file_range(file, crash_line-10, crash_line+10)
  4. Diagnose:
     NullPointerException         → null check missing
     IndexOutOfBoundsException    → bounds check missing
     NetworkOnMainThreadException → network on UI thread
     ClassCastException           → wrong type cast
  5. patch_file() fix + build_project() test

RULES:
  ✗ Never guess fix without reading logs first
  ✗ Never fix more than one error per cycle
  ✗ Never delete code to silence errors — fix the actual problem
  ✓ Cascading errors disappear when root cause is fixed
